# Memory RAG 功能测试用例

## 1. 测试目的

本文档用于记录 Memory RAG System 的核心功能测试结果，重点验证系统是否能够完成以下基础闭环：

1. 身份类 / 闲聊类 Query 是否能够被轻量 QueryPolicy 拦截；
2. 基础知识库问答是否能够正常触发 Base Knowledge 检索；
3. 普通知识问答是否不会错误写入 User Memory；
4. 用户目标、计划、偏好类信息是否能够写入长期记忆；
5. 历史记忆回忆类问题是否能够触发 User Memory 检索；
6. 程序重启后，长期记忆是否仍然能够持久化召回。

## 3. 测试前准备

为避免历史脏数据影响测试结果，测试前需要清空动态长期记忆库。

### 方式一：命令行删除

在项目根目录执行：

```bash
rm -rf ./storage/user_memory
```

### 方式二：PyCharm 手动删除

在 PyCharm 项目目录中手动删除：

```text
./storage/user_memory
```

注意保留基础知识库：

```text
./storage/base_knowledge
```

重新运行系统后，控制台应显示：

```text
动态记忆库: 加载完毕，当前拥有 0 条历史记忆。
```

## 5. 详细测试记录

### TC-01：身份类 Query 拦截

#### 用户输入

```text
你是谁
```

#### 预期行为

系统应直接回答自身身份，不进入基础知识库检索，不被基础知识库中的文本内容带偏。

#### 实际结果

系统回答：

```text
我是一个本地运行的 Memory RAG 助手，可以结合基础知识库、长期记忆和近期对话来回答问题。
如果你问知识库相关内容，我会参考基础知识库；如果你问之前的对话、个人计划或偏好，我会参考长期记忆。
```

#### 测试结论

通过。

身份类 Query 被 QueryPolicy 拦截，未出现《西游记》人物代入问题。

---

### TC-02：基础知识库问答

#### 用户输入

```text
孙悟空是谁
```

#### 预期行为

系统应进入普通 RAG 检索流程，从 Base Knowledge 中召回相关内容，并回答孙悟空相关信息。

#### 实际结果

系统回答了孙悟空相关内容，例如：

```text
孙悟空是齐天大圣的法名，原是东胜神洲傲来国花果山水帘洞人氏……
```

#### 测试结论

通过。

基础知识库检索链路正常。

---

### TC-03：普通知识问答不写入长期记忆

#### 用户输入

```text
孙悟空是谁
```

#### 预期行为

该问题属于基础知识库问答，不属于用户个人目标、计划、偏好，因此不应写入 User Memory。

#### 实际日志

```text
MemoryManager: 当前对话无长期记忆价值，跳过动态记忆写入。
```

#### 测试结论

通过。

MemoryManager 的长期记忆价值过滤生效，避免了知识问答污染用户动态记忆库。

---

### TC-04：用户目标写入长期记忆

#### 用户输入

```text
我的目标是找一份 RAG 实习
```

#### 预期行为

系统应识别该输入为用户目标陈述，直接进行简短确认，并写入长期记忆。

#### 实际日志

```text
MemoryManager: 捕获到新知识，已存入动态记忆库中。
```

#### 实际回答

```text
好的，我已记录这条信息。后续如果你询问相关目标、计划或偏好，我会结合这条长期记忆来回答。
```

#### 测试结论

通过。

`memory_write` 分支生效，用户目标被成功写入 User Memory。

---

### TC-05：当前会话历史记忆回忆

#### 用户输入

```text
我之前说过什么
```

#### 预期行为

系统应触发历史记忆回忆策略，查询 User Memory，并召回用户此前提到的目标。

#### 实际日志

```text
MemoryManager: 当前为历史记忆回忆问题，跳过动态记忆写入。
```

#### 实际回答

```text
根据你的长期记忆，你曾经说过你的目标是找一份 RAG 实习。
```

#### 测试结论

通过。

系统成功召回当前会话中写入的长期记忆，并且没有将“我之前说过什么”再次写入动态记忆库。

---

### TC-06：重启后长期记忆持久化召回

#### 测试步骤

先输入：

```text
exit
```

退出系统后，重新运行 `main.py`。

#### 启动日志

```text
发现现有索引，正在从 ./storage/user_memory 加载...
动态记忆库: 加载完毕，当前拥有 1 条历史记忆。
```

#### 用户输入

```text
我之前说过什么
```

#### 预期行为

系统应在重启后仍然能够从 User Memory FAISS 中召回此前保存的用户目标。

#### 实际回答

```text
根据你的长期记忆，你曾经说过你想要找一份 RAG 实习。
```

#### 测试结论

通过。

User Memory FAISS 持久化生效，程序重启后仍可召回历史记忆。

---

## 6. 测试结论

本轮测试验证了 Memory RAG System 的核心闭环：

1. 身份类与闲聊类 Query 可以被 QueryPolicy 拦截，避免基础知识库污染回答；
2. 普通知识问答可以正常走 Base Knowledge 检索；
3. 普通知识问答不会被错误写入 User Memory；
4. 用户目标、计划、偏好类信息可以被动态写入长期记忆；
5. 历史记忆回忆类问题会跳过动态写入，避免记忆污染；
6. 程序重启后，User Memory FAISS 仍可持久化召回历史记忆。

---

## 7. 测试中发现的问题

本轮测试中，系统核心功能均已通过，但仍观察到以下可优化点：

1. 历史记忆回忆回答中偶尔会出现“根据你的长期记忆”这类提示词痕迹；
2. QueryPolicy 当前仍基于关键词规则判断，泛化能力有限；
3. 当前测试主要依赖人工输入，尚未形成自动化测试脚本。

更完整的系统优化方向见项目 `README.md` 中的 Future Work 部分。
