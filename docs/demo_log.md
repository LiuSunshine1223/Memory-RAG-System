# Memory RAG Demo Log

## 1. Demo 目的

本文档记录 Memory RAG System 的一次完整功能演示日志。

本次 Demo 重点验证：

1. 系统能否正确区分基础知识库与用户长期记忆；
2. 身份类问题是否会被基础知识库污染；
3. 普通知识问答是否不会写入用户长期记忆；
4. 用户目标类信息是否可以被写入动态记忆库；
5. 历史记忆回忆类问题是否可以召回用户长期记忆；
6. 程序重启后，长期记忆是否仍可持久化召回。

---

## 3. 清空动态记忆库后启动

测试前清空 User Memory：

```bash
rm -rf ./storage/user_memory
```

重新启动系统后，控制台输出：

```text
==================================================
 Memory RAG 完整本地版 (GPU 加速已激活)
==================================================
[VRAM Monitor] 显存监控已在后台启动...
 Embedding 加载成功 | 设备: cuda
 Rerank 模型加载完毕！
 发现现有索引，正在从 ./storage/base_knowledge 加载...
 VectorStore: 检测到已有索引，跳过基础知识入库。
 未发现现有索引，正在初始化新索引 (维度: 512)
 动态记忆库: 加载完毕，当前拥有 0 条历史记忆。

[系统就绪] 请开始对话。输入 'exit' 或 'quit' 退出程序。
```

该日志说明：

1. 基础知识库索引已经存在；
2. 动态记忆库已被清空；
3. 当前 User Memory 中没有历史记忆。

## 4. 身份类 Query 拦截

### 用户输入

```text
你是谁
```

### 系统输出

```text
[AI]: 我是一个本地运行的 Memory RAG 助手，可以结合基础知识库、长期记忆和近期对话来回答问题。
如果你问知识库相关内容，我会参考基础知识库；如果你问之前的对话、个人计划或偏好，我会参考长期记忆。
```

### 说明

该用例验证了身份类问题可以被轻量 QueryPolicy 直接拦截，不会进入基础知识库检索，也不会被《西游记》文本中的人物内容带偏。

---

## 5. 基础知识库问答

### 用户输入

```text
孙悟空是谁
```

### 系统日志

```text
MemoryManager: 当前对话无长期记忆价值，跳过动态记忆写入。
```

### 系统输出

```text
[AI]: 孙悟空是齐天大圣的法名，原是东胜神洲傲来国花果山水帘洞人氏，因五百年前大闹天宫，被佛祖困压在西番两界山石匣之内，蒙观音菩萨劝善，是唐僧救出。
```

### 说明

该用例验证了：

1. 普通知识问题可以触发基础知识库检索；
2. 系统能够回答基础知识库相关内容；
3. 普通知识问答不会被写入 User Memory，避免动态记忆污染。

---

## 6. 用户目标写入长期记忆

### 用户输入

```text
我的目标是找一份 RAG 实习
```

### 系统日志

```text
MemoryManager: 捕获到新知识，已存入动态记忆库中。
```

### 系统输出

```text
[AI]: 好的，我已记录这条信息。后续如果你询问相关目标、计划或偏好，我会结合这条长期记忆来回答。
```

### 说明

该用例验证了：

1. QueryPolicy 成功识别用户目标类陈述；
2. 系统没有进入普通 RAG Prompt；
3. 用户目标被写入 User Memory；
4. 回答保持简短确认，避免强行解释基础知识库。

---

## 7. 当前会话历史记忆回忆

### 用户输入

```text
我之前说过什么
```

### 系统日志

```text
MemoryManager: 当前为历史记忆回忆问题，跳过动态记忆写入。
```

### 系统输出

```text
[AI]: 根据你的长期记忆，你曾经说过你的目标是找一份 RAG 实习。
```

### 说明

该用例验证了：

1. 历史记忆回忆类问题触发 User Memory 检索；
2. 系统成功召回用户此前写入的目标；
3. “我之前说过什么”本身没有被再次写入长期记忆；
4. 该机制降低了记忆污染风险。

---

## 11. Demo 总结

本次 Demo 验证了 Memory RAG System 的完整基础闭环：

1. Base Knowledge 与 User Memory 物理隔离；
2. 身份类 Query 可以被轻量 QueryPolicy 拦截；
3. 普通知识问答可以走基础知识库检索；
4. 普通知识问答不会污染用户长期记忆；
5. 用户目标、计划、偏好类信息可以动态写入 User Memory；
6. 历史记忆回忆类 Query 可以单独触发 User Memory 检索；
7. 程序重启后，长期记忆仍然可以被持久化召回；
8. 退出时可以生成显存监控图表，便于观察本地运行资源占用。

---

## 12. Demo 观察

本次 Demo 中，系统已经能够完成“写入长期记忆 → 当前会话召回 → 重启后持久化召回”的核心流程。

当前仍存在一个小问题：历史记忆回忆回答中偶尔会出现“根据你的长期记忆”这类提示词痕迹。该问题不影响核心功能，后续可通过优化 memory_recall Prompt 进一步改善。

更完整的系统优化路线见项目 `README.md` 中的 Future Work 部分。
